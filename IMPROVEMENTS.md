## Project Summary

**Game The Game** is a browser-based multiplayer mini-game tournament platform: players join Socket.IO lobbies, vote on one of ~95 mini-games, wager tournament points, and compete across rounds, with a standalone free-play casino, side-bet gambling games (slots, plinko, wheel, blackjack-lite, chicken cross), a tamagotchi pet system, and a synced "police bodycam" YouTube stream. The architecture is solid and mature — server-authoritative FSM games extending `BaseGame` (`server/src/games/`), a `TournamentManager`/`Scorer` orchestration layer, React 19 + Vite client, shared constants/event names in `shared/`, deployed on Render with Firestore used only for a suggestion box. The codebase is at v2.41.x with an extensive `CLAUDE.md`, but it has significant gaps: known-vulnerable dependencies (1 critical, several high), several unvalidated socket inputs that allow spam/DoS or process crashes, test coverage for only 11 of ~95 server games, no root README, no CI, and a monolithic 1,569-line `server/src/index.js` that mixes HTTP routes, casino games, bodycam sync, and tournament orchestration.

- [x] **Remote-crash vector: unguarded payload destructuring in socket handlers.** *(Fixed 2026-07-09: JOIN_LOBBY destructures inside its try with a lobbyId type check; all 8 casino handlers now take `(data)` and destructure via `data || {}`; CREATE_LOBBY normalizes non-object options; process-level `uncaughtException`/`unhandledRejection` loggers added. Verified live: null payloads to every handler, server stayed up.)* `socket.on(EVENTS.JOIN_LOBBY, ({ lobbyId, code }, callback) => …)` in `server/src/index.js` (~line 270) throws a `TypeError` if a client emits `JOIN_LOBBY` with a `null`/non-object payload — the destructure happens before the `try` block, and an uncaught exception in a Socket.IO listener crashes the whole Node process. Same pattern in `COIN_FLIP`, `SLOTS_SPIN`, `PLINKO_DROP`, `WHEEL_SPIN`, `BJ_LITE_START`, `BJ_LITE_ACTION`, `CHICKEN_START`, `CHICKEN_ACTION` (`({ amount }) => …`, `({ action }) => …`). Normalize every handler to accept `(data = {})` or validate `typeof data === 'object'` first, and add a process-level `uncaughtException`/`unhandledRejection` safety-net logger.

- [x] **`SET_AVATAR` crashes on casino lobbies.** *(Fixed 2026-07-09: casino lobby now includes `avatars: {}` and `LobbyManager.setAvatar` defensively initializes `lobby.avatars`. Verified live: SET_AVATAR after CASINO_JOIN returns success.)* `CASINO_JOIN` (`server/src/index.js` ~line 1063) creates a fake lobby `{ id, players, nicknames, status }` **without an `avatars` field**. If a casino player then emits `SET_AVATAR`, `LobbyManager.setAvatar` (`server/src/lobby/LobbyManager.js` line 87) executes `lobby.avatars[playerId] = avatar` → `TypeError` → process crash (uncaught in an async handler). Add `avatars: {}` to the casino lobby object and a defensive `if (!lobby.avatars) lobby.avatars = {}` in `setAvatar`.

- [x] **`CHAT_SEND` has no rate limit and no length cap.** *(Fixed 2026-07-09: 500ms per-socket cooldown (matches EMOTE_SEND), `typeof text !== 'string'` guard, and `.slice(0, 500)` cap.)* Every other social event (`EMOTE_SEND` 500ms, `GIF_SEND` 12s, `TOMATO_SEND` 30s, suggestions 60s) is rate-limited, but chat (`server/src/index.js` ~line 345) broadcasts `text.trim()` unbounded — a client can flood the lobby with multi-megabyte messages at unlimited frequency (bandwidth DoS on every connected client). Add `.slice(0, 500)` and a per-socket cooldown like the emote handler.

- [x] **`AI_IMAGE_SEND` broadcasts arbitrary client-supplied `imageUrl` with zero validation.** *(Fixed 2026-07-09: client-supplied `imageUrl` must be an `https://images.pexels.com/` URL ≤2048 chars (mirrors GIF_SEND's Klipy whitelist) with a 5s per-socket cooldown; the Pollinations generation path is unchanged and keeps its global cooldown.)* In `server/src/index.js` (~line 503), if `data.imageUrl` is set the server relays *any* string (any external URL, any-size base64 data URI, offensive content) to the entire lobby, bypassing the Pollinations generation path and its rate limit entirely. Compare with `GIF_SEND`, which whitelists Klipy CDN origins. Validate allowed origins (e.g., Pexels URLs from the `/api/image-search` proxy, `data:image/` URIs under a size cap) and add a per-socket cooldown.

- [x] **No size limits on nickname or avatar payloads.** *(Fixed 2026-07-09: nickname capped at 24 chars; client-supplied avatars must be a Pexels URL ≤2048 chars or a `data:image/` URI ≤300K chars (~220KB image) — verified live that other origins are rejected. The "broadcast avatars once via AVATAR_UPDATE instead of embedding in every state payload" optimization was NOT done — larger refactor.)* `SET_NICKNAME` (~line 229) trims but never caps length; `SET_AVATAR` accepts an unbounded base64 string that is stored in `socket.data`, `lobby.avatars`, and `tm.avatars`, then re-broadcast inside **every** `LOBBY_STATE`, `TOURNAMENT_STATE`, and `GAME_STATE` payload — a single multi-MB avatar amplifies all subsequent broadcasts to all players. Cap nickname at ~24 chars and avatar at ~200KB, and consider broadcasting avatars once (`AVATAR_UPDATE` already exists) instead of embedding them in every state payload.

- [x] **Null-lobby crash in `GAME_ACTION` broadcast path.** *(Fixed 2026-07-09: `if (!lobby) return;` guard added after `getLobby`, matching the `setOnStateChange` callback.)* In `server/src/index.js` (~line 1156), after `game.handleAction`, the code does `const lobby = lobbyManager.getLobby(lobbyId); const nicknames = lobby.nicknames || {}` — if the lobby was deleted between action and broadcast (race with the last leave), `lobby` is `null` and the handler throws uncaught. Guard with `if (!lobby) return;` like the `setOnStateChange` callback already does.
